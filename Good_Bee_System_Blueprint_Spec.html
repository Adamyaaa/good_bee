1. Executive Summary & Platform Purpose

Good Bee is an end-to-end, multi-stakeholder D2C and B2B botanical skincare commerce ecosystem. It combines a high-speed consumer storefront with specialized operational portals for wholesale dealers, formulation laboratories, and administrative control. This document provides a complete technical and functional blueprint so that any development team can replicate or adapt this architecture for similar multi-tiered e-commerce applications.

D2C Public StorefrontConsumer

1:1 square media presentation, concern-based skin filters, real-time inventory checks, instant dynamic UPI QR checkout, and order timeline tracking.

B2B Wholesaler DeskWholesale

Minimum Order Quantity (MOQ = 20) rules, automated volume tier discounting (30% to 50% off), instant margin calculators, and PO generation.

Vendor & Lab PortalSupply

Producer R&D portal for formulation submissions, batch volume declarations, Certificate of Analysis (CoA) verifications, and pricing proposals.

3. Global System Topology & High-Level Architecture

Core Architectural PrinciplesArchitectural Pattern

Good Bee uses a decoupled, event-driven Single Page Application (SPA) architecture designed for zero cold-start latency, seamless offline recovery, and deterministic role separation.

Frontend Layer (Vite + React 18):
  • Atomic Component Isolation: Storefront, Portals, Modals, and Checkout are decoupled modules.
  • CartContext & Global State: Reactive React Context managing cart count, totals, coupons, and local persistence.
  • Hash-Based Direct Deep Linking: Supports #product=ID and #concern=ID for direct landing and sharing without full page refreshes.
Dual-Sync Resilience Engine:
  • Mock-First Storage Fallback: LocalStorage seeds provide a 100% operational experience immediately.
  • REST API Abstraction Layer: api.js routes requests to live Express backend if online, seamlessly falling back to local storage if offline or during server cold-starts.
  • State Consistency: Catalog updates in Admin CMS reflect instantly across the active storefront session.

Shopping Bag & Cart LogicClient State
  • Reactive Item Management: Dynamic addition, quantity increments, decrements, and removals.
  • Free Shipping Threshold: Automatically applies free express courier delivery when order subtotal exceeds ₹999; otherwise computes standard ₹70 courier fee.
  • Promotional Coupon System: Validates discount coupon codes (e.g. HONEY15 = 15% discount) and updates subtotal in real time.

Dynamic UPI & COD CheckoutPayment Flow

7. B2B Wholesaler Desk (Bulk Commerce Subsystem)

The Wholesaler Desk provides authorized commercial distributors, spas, and boutique retail stockists with a dedicated high-volume procurement interface. It replaces manual quotation emails with programmatic volume pricing.

Distributor Qualification & AccessB2B Auth

Partner Modal Gate: Wholesalers access via navigation header modal → Wholesale Desk.
Dealer Identification: Authenticated by GST Number, Dealer Code (e.g. DLR-MUM-01), Company Name, and Registered City.
Credit Terms: Displays dealer margin tier, payment terms (Net-30 / Advance), and lifetime spend history.

Tiered Volume Pricing EnginePricing Rules

Minimum Order Quantity (MOQ): Enforces strict minimum order threshold of 20 units total.
Automated Tier Discounting:
• Tier 1 (20 – 49 units): 30% Wholesale Discount off retail MRP.
• Tier 2 (50 – 99 units): 40% Wholesale Discount off retail MRP.
• Tier 3 (100+ units): 50% Bulk Master Distributor Discount.
Taxation: Programmatically applies 18% GST with full B2B tax invoice credit.

Wholesale Purchase Order LifecycleData Lifecycle
01
Catalog Selection: Dealer inputs unit quantities across individual SKUs in the catalog. Real-time counter validates whether total units satisfy the 20-unit MOQ threshold.
02
Live Margin Computation: System dynamically calculates: (a) Retail MRP Total, (b) Wholesale Discounted Subtotal, (c) 18% GST, (d) Estimated Reseller Margin (in ₹ and %).
03
Quote Generation & Submission: Dealer clicks "Generate Wholesale PO". The order is assigned an ID (e.g. GB-WHL-8821) and dispatched to the Master Admin approval matrix.
04
Consignment Release: Admin reviews the wholesale order, verifies logistics freight, and marks it approved for warehouse pallet dispatch.

2. Essential Reusable Engineering Patterns

Dynamic UPI String SynthesisPayments

Construct standard NPCI UPI URI strings client-side: `upi://pay?pa=${vpa}&pn=${brandName}&am=${total}&cu=INR&tr=${orderId}`. Render directly as a QR image via client libraries (qrcode). No payment gateway fee overhead; supports zero-cost instant merchant settlements.

Tiered Wholesale Discount AlgorithmPricing Logic

Calculate discount rates programmatically based on aggregate units: if totalUnits < 20, reject with MOQ error. If 20 ≤ units < 50, apply 30%. If 50 ≤ units < 100, apply 40%. If ≥ 100, apply 50%. Compute GST at 18% on post-discount subtotal.
